A2560Me: fVDI RGB565, XaAES and TeraDesk
======================================

Copy all contents of drive_d to FAT32 D:, merging folders. Startup now
loads D:/MINT/FVDI/FVDI.PRG before XaAES, then D:/DESKTOP/DESKTOP.PRG.
Keep C: and its validated FreeMiNT kernel. Preserve TERADESK.INF settings.
DDR-aware EmuTOS is required. RAM boot is temporary; permanent colour
startup also needs that firmware installed in flash.

The updated driver keeps CPU data caching enabled with write-through RAM
mappings and uses VDMA for large RGB565 copies and solid replacement fills.
Other raster operations, patterned drawing and the cursor use CPU routines.
Video Options lists actual Foenix modes at the active timing. Choose full
or half resolution through MINT/FVDI/FVDI.SYS before AES starts; live Atari
Setscreen changes are not supported.

Run MINT/FVDI/DMATEST.TOS to verify cached CPU writes, DMA copy/fill,
cached readback and overlap handling in reserved off-screen DDR. See
MINT/FVDI/README.TXT for full validation and recovery instructions.
Test scrolling, typing, menus, overlapping windows and dragging performance.
Cache/VDMA target diagnostic passed on 2026-10-17. The user confirmed
responsive window dragging with no corruption. Video Options visually passed with the correct current mode and valid
Foenix RGB565/monochrome list; actual half-mode switching not tested.

Recovery: copy MINT/MONO.CNF over MINT/MINT.CNF for monochrome, or use
MINT/SHELL.CNF for the internal shell. Both need a reboot to take effect.
Sources: MINT/SOURCE/FVDISRC.TGZ and FVDI.TXT; desktop patch TERAVID.PAT,
TDBUILD.SH and TERASRC.TGZ. Original upstream binaries remain in TERABIN.ZIP.
